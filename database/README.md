# Database Service Documentation (GearBids)

## Overview
The **Database Service** is the relational data backbone of the GearBids auction platform. It runs on **PostgreSQL 15+** (deployable either on **Amazon RDS PostgreSQL** or a managed **EC2 PostgreSQL instance**). It persists user accounts, session state, vehicle specifications, active/historical auctions, bids, anti-sniping events, comments, outbid notifications, and automated inspection reports.

---

## Entity Relationship Overview

```
 [users] 1 ──── * [sessions]
    │
    ├── 1 ──── * [auctions] (as seller)
    ├── 1 ──── * [bids] (as bidder)
    ├── 1 ──── * [comments] (author)
    └── 1 ──── * [notifications] (recipient)

 [vehicles] 1 ──── 1 [auctions]
     │
     └── 1 ──── * [inspections]

 [auctions] 1 ──── * [bids]
     │
     └── 1 ──── * [comments]
```

### Table Dictionary
- `users`: User profiles, bcrypt-hashed credentials, roles (`is_seller`, `is_admin`), avatar and location.
- `sessions`: Persistent HTTP session store for Express (`express-session` backed by database).
- `vehicles`: Rich automotive data (VIN, Year, Make, Model, Trim, Mileage, Transmission, Engine, Highlights, Equipment, Known Flaws).
- `auctions`: Auction lifecycles (`ACTIVE`, `ENDED`, `SOLD`, `RESERVE_NOT_MET`, `CANCELED`), current high bid, reserve price logic, closing timestamps, anti-sniping extension markers.
- `bids`: Complete audit trail of bids placed per auction with timestamps.
- `comments`: Community Q&A feed between sellers and prospective bidders.
- `notifications`: Asynchronous events (e.g. `OUTBID`, `AUCTION_WON`) consumed by frontend alerts.
- `inspections`: Pre-purchase inspection & condition scores generated by the Inspection Microservice.

## Configuration & Environment Variables

| Variable | Description | Default (Local) | Production (AWS) |
|---|---|---|---|
| `DB_HOST` | Hostname or IP of PostgreSQL instance | `localhost` | RDS Endpoint or private EC2 IP |
| `DB_PORT` | PostgreSQL port | `5432` | `5432` |
| `DB_USER` | Database username | `postgres` | SSM Parameter `/gearbids/{env}/db_user` |
| `DB_PASSWORD`| Database password | `postgres` | SSM Parameter `/gearbids/{env}/db_password` |
| `DB_NAME` | Database catalog name | `gearbids` | `gearbids` |
| `DB_SSL` | Enable SSL encryption | `false` | `true` (for RDS) |

## How to Run Migrations & Seeds

### Local Development (via Docker or local PostgreSQL)
```bash
# Run schema only
./database/migrate.sh schema

# Run schema and seed realistic Cars & Bids data
./database/migrate.sh seed
```

### Remote AWS EC2 / RDS execution via AWS SSM
Students do **not** use direct SSH with open security groups. Instead, run migrations from the management EC2 or CI/CD runner using AWS Systems Manager Run Command:
```bash
aws ssm send-command \
  --instance-ids "<BACKEND_EC2_INSTANCE_ID>" \
  --document-name "AWS-RunShellScript" \
  --parameters 'commands=["cd /opt/gearbids/database && ./migrate.sh seed"]' \
  --region eu-west-1
```
